# Visual Grouping Speed Study

A single-page web app for running a human perception study that measures how quickly people can classify images from the **STL-10** dataset depending on how well-arranged they are in a grid. The goal is to empirically demonstrate that higher grid layout scores (i.e. visually similar images placed near each other) lead to faster human processing times and validate the metric against real user performance.

---

## What It Does

Each participant is shown **one grid of 100 STL-10 images** and asked to label each image with one of the 10 STL-10 class categories. The time it takes to label all 100 images is recorded. The layout shown is **randomly selected** from the `LAYOUT_POOL` (a set of SA-optimized grid arrangements) on each page load.

---

## STL-10 Dataset

The study uses [STL-10](https://cs.stanford.edu/~acoates/stl10/), a 10-class image recognition dataset derived from ImageNet. The 10 classes — in the alphabetical order used when extracting CLIP features — are:

| Index | Class    | Emoji |
|-------|----------|-------|
| 0     | Airplane | ✈️    |
| 1     | Bird     | 🐦    |
| 2     | Car      | 🚗    |
| 3     | Cat      | 🐱    |
| 4     | Deer     | 🦌    |
| 5     | Dog      | 🐶    |
| 6     | Horse    | 🐴    |
| 7     | Monkey   | 🐒    |
| 8     | Ship     | 🚢    |
| 9     | Truck    | 🚛    |

Sample images are served from `stl10_sample/<class_name>/<NNN>.jpg` (e.g. `stl10_sample/airplane/000.jpg`). Each class contributes 10 images (indices 000–009), for 100 images total per grid.

---

## Layout Pool & Grid Scoring

Layouts are generated by a **Simulated Annealing (SA)** optimizer that rearranges the 100 images based on CLIP embeddings. Each entry in `LAYOUT_POOL` represents a saved SA checkpoint:

```js
{
  step:       1550,       // SA iteration when this snapshot was saved
  dpq:        0.880517,   // SA objective value (used for deduplication)
  grid_score: 265.036039, // 
  ordering:   [ 31, 39, … ] // Flat row-major source-image indices (0–99)
}
```

`ordering` is a permutation of 0–99, where index `i` encodes class `Math.floor(i / 10)` and sample `i % 10`.

## App Flow

1. **Welcome screen** — brief explanation of the task
2. **Practice round** — an untimed 4×5 grid of 20 images to familiarize participants with the labeling UI
3. **Timed grid** — a 10×10 grid of 100 STL-10 images; timer starts the moment the grid renders
4. **Done screen** — shows the completion time and accuracy, and saves results to Google Sheets

---

## Labeling Interaction

- A sidebar lists all 10 STL-10 class labels, each with a color dot and emoji
- The participant clicks a label to select it, then clicks images in the grid to assign that class
- Clicking a labeled image again **removes** the label (toggle behavior)
- Clicking a labeled image with a **different** label selected overwrites the assignment
- A counter next to each label tracks how many images have been assigned to it
- The timer stops automatically the moment the 100th image is labeled

---

## Data Collected

Each submission saves one row to Google Sheets with the following fields:

| Field | Description |
|---|---|
| `Timestamp` | Pacific time when the result was submitted |
| `Participant ID` | Randomly generated 8-character anonymous ID |
| `Grid Score` | Numerical layout quality score of the shown grid |
| `Grid Time (s)` | Seconds taken to label all 100 images |
| `Grid Accuracy (%)` | Percentage of images assigned to the correct STL-10 class |
